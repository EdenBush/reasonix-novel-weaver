# Phase 4：自动校验与修复

**目标**：确保所有章节完成且字数达标，全程无需用户介入。这是融合版的质量兜底——Reasonix 1.x 缺这一环，Chinese Novelist 的"自动重写"让它变得可靠。

```
本阶段执行清单：
[ ] 1. 【必须】status → validating
[ ] 2. 【必须】逐章检查：文件存在 + 字数脚本 + 质检摘要齐全（含 AI 味自评/衔接/逻辑行）+ 执行痕迹检查（清单勾/台账更新/伏笔登记）
[ ] 3. 【必须】读者体验抽检（锚点章三层验证）
[ ] 4. 【必须】不合格章自动修复（≤3 轮，按专家介入对照表）
[ ] 5. 【必须】全部通过 → status → completed → 完成报告
→ 清单全勾 + 全部章节 PASS = 本阶段完成，进入 Phase 5
```

---

## 校验流程

### 1. 初始化校验

读取 `novel-output/{小说名}/02-写作计划.json`，将项目 `status` 更新为 `"validating"`。

### 2. 逐章检查

对每一章执行以下检查：

1. **文件存在性**：检查 `filePath` 指定的文件是否存在
2. **字数检查**：运行脚本
   ```bash
   python scripts/check_chapter_wordcount.py --all novel-output/{小说名}/
   ```
3. **质检档案检查（含执行痕迹）**：`04-质检档案.md` 中是否每章都有记录，且每条必须包含以下**执行痕迹字段**（缺一即视为该章流程未走完，判不合格）：
   - `AI 味自评：人侧 X/10`（证明 AI 味自评量表执行过）
   - `衔接检查：通过/未通过`（证明写前锚点与衔接三查执行过）
   - `逻辑检查：通过/未通过`（证明 BUG 四查执行过）
   - `硬性句式扫描：已清零`（证明拦截执行过）
   - `质量评分：XX/80`（证明评分卡执行过，参考 quality-scorecard.md）
   - `专项检查：对话-master / 情绪-master / 节奏-check`（证明排班制执行过——对话每章必调、情绪偶数章加调、锚点章全调、每 3-5 章节奏；**缺专项检查记录 = 排班未执行 = 不合格**）
   另抽查：`01-大纲.md` 章节摘要区是否已追加本章摘要、伏笔对照表是否同步、`03-状态台账.md` 出场人物是否已写回终态——**缺痕 = 未做 = 不合格**
4. **正文纯净检查**：章节文件正文中**不应出现**【本章质检摘要】等质检痕迹（如发现旧版遗留，从正文移除）
5. **质量曲线汇总**：所有章节评分汇总，生成全书质量曲线（章节号 × 总分）——连续 3 章 < 65 分标记"低潮区"；锚点章 < 70 分必须回炉
6. **读者体验抽检**（来自 Reasonix Reader Simulator）：对品质锚点章（`qualityLevel: "anchor"`，至少覆盖开篇、中点、高潮各一章）做三层读者验证：
   - **普通读者视角**：不分析技巧，只看好不好看、想不想继续翻——给感性反应
   - **挑剔读者视角**：找"疙瘩"——让读者从沉浸中被迫抽离的瞬间（逻辑对不上、反应不合理、转折没铺垫）
   - **作者同行视角**：欣赏 + 建设性心得
   发现"疙瘩" → 标记到对应章节的修复清单
7. **更新 JSON**：将 `wordCount` 和 `wordCountPass` 写入对应章节记录

### 3. 汇总结果

- **全部通过**（所有章节文件存在、`wordCountPass == true`、质检摘要齐全）→ 更新项目 `status` 为 `"completed"`，进入 Phase 5
- **有不通过** → 进入步骤 4

### 4. 自动修复（最多 3 轮）

对每个不通过的章节：

1. 将 `status` 设为 `"failed"`，`retryCount` 加 1
2. **诊断失败原因**（见下方「专家介入对照表」，这决定修复方式）
3. 回到 Phase 3 对该章节执行逐章创作流程（写前分析→撰写→质检→修改→收尾）
4. 修复完成后重新检查字数与质检摘要
5. 更新 `02-写作计划.json`

### 专家介入对照表

**子技能已安装时为首选（必须调用，专业版）；内建指南仅作兜底（子技能未装时）。**

| 失败原因 | 首选处理（调用子技能） | 内建兜底 |
|---------|----------------------|---------|
| 字数不足 | `reasonix-novel-pad`（专业补字） | 补字 SOP（悬空瞬间/沉默间隙/过渡空白 + 质感三问） |
| AI 味重（自评 4 项以上 AI侧） | `reasonix-novel-deai`（六步深度清洗）+ 自评复评 | DeAI 六步工作法（deai-workflow.md） |
| 硬性句式残留 | 逐句重写（杀干净） | — |
| 没毛病但差口气 | `reasonix-novel-write-master`（单点手术） | 六维诊断 |
| 对话生硬 | `reasonix-novel-dialogue-master` | 台词换人说测试（dialogue-writing.md） |
| 情绪没推上去 | `reasonix-novel-mood-composer` | 落差/蓄能/释放诊断 |
| 平淡无聊 | `reasonix-novel-thrill-booster` | 十色爽点（thrill-panel.md） |
| 读者抽检有"疙瘩" | 一致性四问 + 杠精自检定位 | — |
| 剧情断档/BUG | 衔接三查 + 逻辑 BUG 四查（continuity-check.md） | — |

**循环规则**：
- 最多执行 **3 轮** 校验-修复循环
- 超过 3 次仍不合格的章节，保留记录但不阻塞流程（在完成报告中标注）
- 所有修复完成后更新项目 `status` 为 `"completed"`

向用户展示创作完成总结：

```
📊 《[小说名称]》创作完成

总章数：[X] 章
总字数：[X] 字
完成率：[X]%

各章节状态：
✅ 第1章：[标题]（[字数]字）
✅ 第2章：[标题]（[字数]字）
...

项目文件夹：novel-output/[小说名称]/
```

如有不合格章节（超过 3 次重写仍未通过），在报告中标注：

```
⚠️ 第X章：字数不足（[实际字数]/3000），已重试3次
```

**报告之后**：进入 Phase 5 完稿润色。
